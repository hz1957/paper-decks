# 科研选题收敛与验证

把直觉转成可证伪、能执行、可追溯的研究问题。围绕用户的真实任务和资源约束收敛，不以生成大量点子或承诺“能发顶刊”为目标。

## 入口与范围

- 先查看用户提供的论文、笔记和已有选题记录，复用已知信息。识别当前需要的是拆论文、争议地图、导师追问、审稿预演，还是完整流程；只执行所需阶段。
- 完整流程按下面五步推进；已有可靠产物时从缺失阶段接续。缺少前序证据仍可做初步审查，但标明结论依赖哪些未核验前提。
- 建立一张范围表：真实应用任务、研究对象与评价指标、已有论文、可用数据与方法、人员/设备/算力/预算/周期、目标读者或期刊。每项标记“已确认 / 待确认 / 规划假设”。
- 只问会影响下一步判断的缺项。任务尚不具体时先问任务；已能拆论文或检索时继续做，不因次要信息缺失停住全部工作。
- 默认用中文、表格和要点交付；保留论文标题与必要原文。未给周期时，可暂按三个月安排最小验证，并明确这是规划假设。未给目标期刊时按领域严格审稿标准评估，不自行指定期刊。

## 证据约束

- 给论文、关键主张、空白、假设和实验分配稳定编号 `P / C / G / H / E`，使最终主张能追到原始证据。来源至少包含 DOI 或稳定链接、版本/日期、页码或章节及图表编号；无法定位的字段写明缺失。
- 区分“作者报告的结果”“已核对的图表证据”“本次推断”“待验假设”。读过摘要不等于读过全文，读过图注不等于看过图，论文报告结果不等于已独立复现。
- 只引用实际打开并核对的材料。搜索摘要可作线索，不能独自支撑关键的新颖性或实验结论。没有检索工具或全文权限时，如实记录覆盖限制，继续做可完成的部分。
- 原文引用保留原语言、位置和短摘录；中文解释另列。遵守来源的引用限额；对非用户提供的网页/文献，同一来源的逐字引用保守控制在合计 25 个词内，其他语言按等效短摘录保守控制，更多内容用转述与定位。多处重复摘录也计入总量。
- 不将“作者没讨论”写成“作者承认的局限”，不将缺失信息写成已发现缺陷，不将相关性写成因果，不编造样本量、指标、误差、数据可得性或实验结果。
- “未检索到”只代表指定范围和时间内的检索结果。允许的结论是“截至某日，在列明的检索范围内，尚未发现直接解决 X 的工作”；不得升级为“确实没人做”“首个”或“已证明空白”。

## 第一步：拆论文

执行本步时读取 [论文与争议地图模板](references/literature-and-search.md)。逐篇形成五个模块，只输出表格和要点：

1. **文献信息与摘要**：研究问题、核心主张、论文版本和证据可访问范围。
2. **数据来源与分析方法**：对象、样本、来源、纳排标准、划分方式、对照、统计或建模方法、可复现信息。
3. **主要结果与证据链**：主张 → 数据与对照 → 结果及不确定性 → 支撑位置 → 能支持到哪一步。
4. **逐图结论**：逐张覆盖主文图；需要时拆到 panel，补充关键表格及支撑核心主张的补充材料。检查坐标、单位、样本、误差条含义、比较对象和统计标记。没有看见图就标“图像未核验”。
5. **局限与弱点**：分开列作者明确声明的局限、作者提出的未来方向，以及有证据依据的分析者疑点；对疑点写出替代解释和核验办法。

把需要用户复核的数据、图表或实验细节列成短清单。全文、补充材料或图像不可用时保留缺项，不用领域常识补全。

## 第二步：画争议地图并反向检索

继续使用 [论文与争议地图模板](references/literature-and-search.md) 的检索记录与地图格式。

- **共识区**：记录结论成立的对象、条件和证据独立性。共用数据、方法或团队的依赖关系应单列，不能仅凭论文数量判断独立验证次数。
- **分歧区**：先排除任务、数据分布、终点定义、评价指标、统计功效或资源预算不同导致的不可比，再讨论真正矛盾。把“可能原因”标为假设，并提出能区分解释的实验。
- **空白区**：区分作者呼吁、已知但尚未解决的问题、已有局部解法、检索后仍待确认的缺口；Future Directions 仅提供检索线索，不自动证明新颖性。
- 为候选空白检索问题本身、同义表述、邻近领域、已有替代解法、反例及引用链。主动寻找能推翻新颖性主张的工作；打开最接近工作的原文，按相同任务与约束核对差异。
- 记录实际日期、数据源、完整检索式、过滤条件、筛选范围、代表命中、纳入/排除理由和访问限制。尽可能交叉使用不同文献入口；覆盖不足就降低结论强度。
- 每个候选空白必须回答：已有工作解决到哪里；剩余差别是什么；差别为何有实际或科学价值；用户的资源如何切入。只改模型名称、组件或组合方式，尚不能构成研究问题。
- 单独保留每篇论文的 Limitation / Future Directions 短原文索引。全文未获取与全文中未找到明确表述要分别记录。

本步结束给出少量值得继续核验的候选问题及其证据强弱。没有站得住的候选时如实报告，并说明需要补搜的范围。

## 第三步：逐轮导师追问

执行本步时读取 [追问、审稿与沉淀模板](references/validation-and-decisions.md)。严格质疑论证，语气保持专业。

每轮围绕一个核心问题追问，等待用户回答后再推进。工具支持异步提问时可用该工具；等待期间仅推进不依赖答案的证据工作。不要一次倾倒整套问卷，不代填用户的任务、数据条件、研究动机或承诺。

依次核实；上下文已经清楚的问题不重复问：

1. **真实任务**：谁在什么场景下，用什么输入做什么决策？当前失败的代价是什么？
2. **默认条件**：现有最强方法和最简单可行基线分别依赖哪些条件？依据在哪里？
3. **现实违背**：哪个条件会在实际场景中失效？已有观测，还是尚待验证的猜想？
4. **实质差别**：方案改变了哪项可检验的假设或能力？如何排除换组件、增加数据、算力或调参带来的收益？
5. **可证伪性**：哪些目前只能写成假设？看到什么结果会承认它不成立？最小区分实验是什么？

遇到“更泛化”“更可靠”“没人做过”等含糊回答，指出缺少的对象、条件、比较项或可观测量，继续问同一个问题。可以解释什么样的答案足够具体，但不能把示例当作用户事实。

若用户要求先出草案，可用明确标注的假设给出条件式方案；不可伪造一轮已经完成的问答。尚未回答的决定性问题保持开放。

本步产出“研究问题—现实约束—待验假设—证据路径”表。每条假设还需有最接近工作、简单基线、最小实验、反证条件和资源缺口；达不到时明确缺项，不包装成已成熟选题。

## 第四步：模拟严苛审稿

使用 [追问、审稿与沉淀模板](references/validation-and-decisions.md) 的三份报告格式。已知目标期刊时结合其实际范围评估；涉及现行投稿要求时核查官方来源，不编造编辑偏好或录用概率。

1. **拒稿理由**：给出最关键的三条 major concerns；每条关联具体主张或证据缺口，说明致命程度、补强证据，以及何种结果仍不足以消除质疑。不足三条有依据的问题时说明，不凑数。
2. **可行性拆解**：按创新性、数据可得性、技术可实现性、周期可控性、预期贡献五方面评 1–5 分。统一高分代表更有利，未知记“待评”，并附依据、置信度及改变评分所需证据；不用平均分掩盖决定性短板。
3. **补强清单**：区分立项前最小验证与投稿前必要证据，标注优先级、依赖、成本/时间区间、成功与失败判据、三个月内是否可完成。周期是依据已知条件的估计，不把计划写成已运行结果。

优先投入“低分且能用小成本实验改善判断”的项。关键数据无法在约束内取得、核心命题无法识别，或创新主张已被最接近工作覆盖时，建议缩小问题、转换问题或终止当前主张，并列明依据；未知信息本身不等于应该放弃。

## 第五步：沉淀并迭代

把论证沉淀为可继续更新的研究记录，而非只留聊天结论。使用 [追问、审稿与沉淀模板](references/validation-and-decisions.md) 的决策卡与实验计划。

- 沿用用户已有文档位置。没有约定时写入当前工作区的 `research/<topic-slug>/`，不要把研究结果写回 skill 安装目录。
- 按实际完成阶段创建 `00-scope.md`、`01-papers.md`、`02-map.md`、`03-hypotheses.md`、`04-review.md`、`05-decision-log.md` 与 `search-log.md` 中需要的文件，不生成空文件来假装完成流程。
- 决策卡记录：当前问题与候选贡献、证据索引、已核验事实、未验假设、被否决方向及原因、最小验证、成功/停止/转向判据、下一步和待答问题。资源与截止时间未经用户确认就注明。
- 实验计划先安排能最快推翻核心假设的验证，再安排扩大样本或完整系统。给出依赖、基线与对照、评价方法、不确定性处理、资源估计及失败后的动作；阈值需有来源，尚待确定时保留待定。
- 新论文、负结果或资源变化出现时，更新受影响的主张和评分，保留日期、旧判断、变化原因与证据，不悄悄改写选题历史。进入正式立项或投稿判断前刷新最接近工作的检索。
- 交付时区分已完成分析、已执行实验和仅有计划；链接实际产物，并给出当前建议：继续核验 / 缩小范围 / 转向 / 终止当前主张。

## 交付前检查

- 是否覆盖了本轮承诺阅读的论文与图，并明确未访问部分？
- 新颖性判断是否带实际检索记录、最接近工作和截止日期？
- 每个重要结论是否有证据来源，事实、推断和假设是否分开？
- 每条核心假设是否能被具体结果推翻，并有公平基线与可执行验证？
- 三份审稿报告是否把证据不足、已知缺陷和资源限制区分清楚？
- 决策记录是否足以在下次继续，且未把用户未回答的内容写成事实？
