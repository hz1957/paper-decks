# 《Large Language Monkeys: Scaling Inference Compute with Repeated Sampling》解读

> Brown, Juravsky, Ehrlich, Clark, Le, Ré, Mirhoseini — Stanford / Oxford / Google DeepMind, arXiv:2407.21787
>
> 论文原文：[large-language-monkeys.pdf](large-language-monkeys.pdf) | [项目主页](https://scalingintelligence.stanford.edu/pubs/large_language_monkeys/)

---

## 一句话概括

**与其训练更大的模型，不如让一个"弱模型"对同一道题反复采样很多次** —— 只要答案能被验证，覆盖率（做出正确答案的比例）会随采样数近乎对数线性地增长，弱模型 + 多次采样可以打败强模型 + 单次尝试。

标题"大语言猴子"来自"无限猴子定理"：猴子随机敲键盘终会敲出莎士比亚 —— 只要给足够的采样次数。

---

## 两个核心概念（全文的骨架）

论文把"重复采样"拆成两个正交问题：

| 概念 | 含义 | 对应的验证手段 |
|---|---|---|
| **Coverage（覆盖）** | 采样 N 次后，**至少有一个**正确解的题目比例 | 单元测试、Lean 证明检查器 |
| **Precision（精度）** | 能否从一堆样本里**挑出**那个正确解 | 多数投票、奖励模型 |

- 有自动验证器的任务（代码、形式化证明）：coverage 提升 = 成绩直接提升。
- 无验证器的任务（数学应用题）：coverage 只是**理论上限**，实际成绩取决于挑答案的方法。

实验方法（Figure 1）：对每道题用正温度采样生成大量独立候选解（最多 10,000 个），再用领域验证器选出最终答案。

## 四个主要发现

### 1. Coverage 随采样数平滑增长，跨任务跨模型成立（第 2 节）

- **SWE-bench Lite**（真实 GitHub issue）：DeepSeek-Coder-V2 单次只解 15.9%，采 250 次到 **56%**，超过当时单次 SOTA（GPT-4o + Claude 3.5 混合，43%）。
- CodeContests 上 Gemma-2B 从 0.02% → 7.1%（**300 倍**）；MATH 上 Pythia-160M（一个 1.6 亿参数的小模型！）从 0.27% → 57%。
- 唯一例外：Pythia 在 CodeContests 上 1 万次采样全是 0 —— 训练数据里编程内容太少，采样再多次也没用。

### 2. 这不只是"能不能"，还关乎"划不划算"（§2.3）

固定总推理 FLOPs 时，最优策略**因任务而异**：

- MATH / GSM8K / MiniF2F：小模型多采样更划算（8B × 多 > 70B × 少）
- CodeContests：大模型少采样更好（题目太难，小模型采再多也够不着）

SWE-bench 换算成 API 价格（Table 1）：

| 模型 | 单次成本 | 尝试次数 | 解决率 | 总成本 |
|---|---|---|---|---|
| DeepSeek-Coder-V2 | $0.0072 | 5 | 29.6% | $10.8 |
| GPT-4o | $0.13 | 1 | 24.0% | $39 |
| Claude 3.5 Sonnet | $0.17 | 1 | 26.7% | $51 |

DeepSeek 便宜 4.7 倍，解决率还更高。

### 3. Coverage 与采样数遵循幂律 → "推理时间缩放律"（第 3 节）

这是理论上最有趣的部分。类比训练缩放律（loss ~ 训练算力的幂律），作者发现：

$$c \approx \exp(a \cdot k^b)$$

其中 c 是 coverage，k 是采样数。含义：**log(coverage) 随 k 的幂增长**，在很大范围内近似对数线性 —— 即"采样数翻 10 倍，coverage 按可预测的比例提升"。这给了"买多少推理算力能换多少性能"一个可外推的公式。

另一个观察（§3.2）：同一家族（如 Pythia 各尺寸）的 coverage 曲线形状相同，只是水平偏移 —— 大模型相当于把小模型的曲线**向左平移**，说明家族内模型提升 coverage 所需的采样数倍增比例近似恒定。

### 4. 瓶颈：验证方法跟不上采样规模（第 4 节,最关键的警告）

在 MATH 上用 Llama-3-8B：coverage 从 100 次采样的 82.9% 涨到 1 万次的 98.4%，但：

- 多数投票：40.5% → 41.4%（基本没动）
- 奖励模型（Best-of-N / 加权投票）：同样在 **~100 个样本处饱和**

原因很直观：多采样解锁的是那些正确率只有 1% 甚至更低的"大海捞针"题 —— 正确解在样本堆里是**极少数派**，多数投票永远投不出它，奖励模型也识别不出来。

有趣的是，人工检查发现 90%+ 的正确 CoT 推理是忠实可靠的（Table 2）—— 即验证的"信号"是存在的，只是现有方法用不上。

## 细节与坑

- **SWE-bench 有 11.3% 的 flaky 测试**（如 Python set 无序导致结果不稳定），作者跑 11 次测试取多数投票来定 pass/fail（附录 B）。
- **CodeContests 的测试用例有假阴性**：35/122 题存在"官方正确解却通不过测试"的情况 —— 重复采样在这些题上变成"掷骰子"赌输出格式（§4.2.2）。
- **所有实验都是独立采样**：同一 prompt、同一温度，纯靠温度带来多样性，没做多样本间交互、没做执行反馈 —— 这是改进空间，也解释了为什么结果偏保守。
- pass@k 用 Chen et al. 的无偏估计公式（式 1）计算，避免小 k 时的方差问题。

## 讨论与改进方向（第 5 节）

作者指出的三个改进方向：

1. **解的多样性**：目前只靠温度采样；可借鉴 AlphaCode 用不同条件（metadata 标签）诱导多样解法。
2. **多轮交互**：让模型拿到执行/验证反馈后迭代，单次尝试更贵但更可能成功。
3. **从历史尝试学习**：目前各次尝试完全隔离；结合验证器反馈可能加速收敛。

系统层面：重复采样是吞吐优先的工作负载（可大批量、共享前缀的注意力优化），成本低于对聊天 API 发一堆并发请求。

## 为什么这篇文章重要

它发表在 o1 发布（2024 年 9 月）前后，与 "test-time compute scaling" 浪潮（o1 的长链思考、AlphaCode 的百万采样）互相印证：**推理算力是与训练算力平行的另一条缩放轴**。

它系统性给出三条结论：

1. 能涨 —— coverage 在四个数量级的采样范围内平滑提升；
2. 可预测 —— 满足指数化幂律，类似推理版缩放律；
3. 卡在验证 —— 无自动验证器时，主流方法在 ~100 样本处饱和。

后来 Self-Consistency → PRM/ORM verifier → o1 式 RL 推理的演进，正是沿着"第 4 节指出的瓶颈"展开的。

## 任务与模型速查

五个评测任务：

| 任务 | 类型 | 自动验证器 | 采样数 |
|---|---|---|---|
| GSM8K | 小学数学应用题 | ✗（oracle 评估 coverage） | 10,000 |
| MATH | 竞赛数学应用题 | ✗（同上） | 10,000 |
| MiniF2F-MATH | Lean4 形式化证明 | ✓ Lean 检查器 | 10,000 |
| CodeContests | 竞赛编程 | ✓ 测试用例 | 10,000 |
| SWE-bench Lite | 真实 GitHub issue | ✓ 仓库单元测试 | 250 |

主要模型：Llama-3-8B/70B（Base/Instruct）、Gemma-2B/7B、Pythia-70M~12B、DeepSeek-Coder-V2-Instruct（SWE-bench 专用，因上下文长度限制）。
