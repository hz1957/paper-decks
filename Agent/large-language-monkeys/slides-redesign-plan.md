# 《大语言猴子》Slides 重做规划

## 目标

- 将现有 13 页压缩为 9 页，保留论文的完整论证链：问题、方法、主要发现、验证瓶颈、局限与结论。
- 让每页只承担一个明确任务，减少大段文字、截图式论文图和过小标注。
- 论文中的折线图、流程图和对比表优先重绘为可编辑对象；原图只用于核对数据与线型，不直接贴到页面上。
- 以 PPTX 作为可编辑源文件，以 PDF 作为 GitHub Pages 的在线阅读版本；弃用 Reveal HTML 幻灯片。

## 现有版本诊断

1. HTML 缺少 UTF-8 字符集声明，浏览器按错误编码解析时中文会整页乱码。
2. 第 3、4、6、7、9 页同时放大标题、长段解释和论文截图，导致图像标注过小、正文靠近或越过页面边界。
3. 第 4/5 页、第 7/8 页、第 9/10 页分别讲同一发现的“结论页 + 补图页”，信息重复并拉长节奏。
4. 多张论文图以截图形式出现，线条、图例和标签无法在演示文稿里编辑，也难以突出真正需要观众看的曲线。
5. 现有网格背景、卡片边框和大量小标签分散注意力，页面更像网页仪表盘而不是研究分享。

## 视觉规范

- 画布：16:9，留出稳定的标题区和页面边距。
- 字体：中文采用微软雅黑，英文与数字同族排版；主标题不小于 30 pt，正文优先 14–18 pt，图表标签不小于 9.5 pt，页脚可使用 8.5–9 pt。
- 色彩：暖白背景、近黑正文、论文蓝作为主色，绿色用于“正确/可验证”，橙色用于拟合或成本，红色仅表示错误与验证缺口。
- 线条：数据曲线保持 2–3 pt；论文图例中的实线、虚线和颜色语义在全稿统一。
- 图文比例：图形页至少 55% 面积留给图；不在一页内同时使用大表格、长段正文和论文截图。
- 动效：不依赖动画表达关键结论，确保 PDF 中每页信息完整。

## 论文正文复审后的修订

- 明确研究范围是可判定对错的 pass/fail 任务；无自动验证器时，coverage 是 oracle 上限而非真实成绩。
- 第 4 页删除从论文图像估读的中间数据点，仅保留正文明确报告的端点，并补充 Pythia 在 CodeContests 上即使采样 10,000 次仍为 0 的反例。
- 第 5 页补齐固定 FLOPs 下的任务差异：MiniF2F、MATH、GSM8K 更偏向 8B 模型多采样，CodeContests 更偏向 70B 模型少采样。
- 第 6 页同时写出 `log(c) ≈ a·k^b` 与 `c ≈ exp(a·k^b)`，并强调 MiniF2F 等任务拟合偏差明显。
- 第 7 页只使用正文明确报告的 `k=100` 与 `k=10,000` 数值，避免把 Figure 7 的估读点当作精确实验结果。
- 第 8 页限定 flaky-test 的 11 次测试仅用于被识别为 flaky 的题，并加入 105 条正确 CoT 中超过 90% 推理链忠实有效的人工评估结果。
- 结论页加入“非零概率不等于可行预算”的限制，并把系统吞吐与验证成本纳入成本结论。
